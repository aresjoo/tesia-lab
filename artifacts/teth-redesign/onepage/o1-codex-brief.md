# 상세 한 페이지 통합 (Codex, Astra): 구현 화면 검수

## 파운더 지시
전략 상세의 개요, 성과, 거래 탭을 하나로 합친다. 거래내역은 메인에 최근 몇 건을 보여 주고(첨부 참고 화면처럼 "거래내역 >" 제목), 전체는 따로 넘어가는 페이지에서 본다. 정보 탭은 그대로 둔다. 파운더가 고른 것: 탭은 개요와 정보 둘, 순서는 성과 → 판단 기록 → 거래내역, 월별 달력은 유지, 거래내역은 주문 한 건이 한 줄.

## 구현 (배포 전)
- 개요: 성과(지표 넷, 그래프, 시작 이후 수익률, 월별 달력) → 판단 기록(3개 + 더 보기) → 거래내역(최근 5건 + 전체로 이동).
- 지표 넷은 그래프에서 고른 기간(최근 7일, 30일, 3개월, 1년, 전체)을 따른다. 기본은 최근 30일.
- 거래내역 전체 화면: `#/share/s/<id>/all/trades`. 30건씩, 더 보기는 50건씩. "← 개요로".
- 금액과 수량은 1,000 USDT 로 시작한 기준. 시각은 보는 사람의 브라우저 시간대.
- 옛 주소(성과, 활동 탭)는 개요로 연다.
- 코드: `index.html` 의 `mkOvTab`, `mkOvKpi`, `mkdSet`, `mkOrders`, `mkOrdersTable`, `mkOrdersSec`, `mkTradesTab`, 스타일 `.mko`.

## 1부: 독립 비평 (UI 기준)
1. 파운더 지시 충족 여부를 항목별로 PASS / FAIL.
2. 한 페이지의 흐름: 첫 화면에 무엇이 보이고 무엇이 밀려났나. 페이지 길이(1440 약 2,300px, 390 약 5,000px)가 감당할 만한가. 섹션 사이 위계와 여백. 달력의 위치.
3. 지표 넷이 그래프의 기간을 따르는 방식: 사용자가 알아차리나. 기간이 짧을 때 승률이 "-" 가 되는 문제. 목록 카드의 값(30일 수익률, 전체 기간 수익 낸 거래)과 어긋나 보이는 곳.
4. 거래내역: 열 구성, 매수와 매도 구분, 보유 중 표시, 손익률의 위치, 1,000 USDT 기준 표기, 390 의 두 줄 배치, 전체 화면의 길이와 더 보기. 숫자 검산(세 판단 방식에서 각 5건 이상: 가격, 수량, 합계, 손익률을 엔진 기록과 대조).
5. 동작과 회귀: 기간 전환, 거래내역으로 이동과 돌아오기, 브라우저 뒤로 가기, 옛 주소, 정보 탭, 판단 기록의 낱말 설명, 달력 월 이동, 따라가기 시트, 목록 카드.
6. **P0, P1, P2 개수를 명시. 0 이면 0 이라고 쓴다.** P0 는 주요 흐름 차단, P1 은 파운더 지시 미충족이나 틀린 숫자나 초보가 잘못 이해하게 만드는 것, P2 는 다듬기.
