# 구현 검증 (Codex, Astra): 전략 찾기 검수 반영, 따라가기 계산 수정, 표기 정리

## 배경
앞선 검증(`artifacts/teth-redesign/sync/s1-codex.md`)과 개선안 검수(`ux-audit/finder-h/R1-codex.md`, `CRIT-claude.md`)의 결과를 Claude 가 제품(`index.html`, 작업 폴더, 아직 커밋 전)에 구현했다. 너는 실제 화면과 실제 함수로 검증한다. 정적 서버는 `http://127.0.0.1:8765/index.html`.

## 파운더 확정 (재론 금지)
- 상세 성과 줄: 승률과 거래 수는 전체 기간. 승률 정렬에서 거래 적은 전략은 배지 없이 뒤로.
- 카드에 최대 낙폭을 되돌리지 않는다.
- 그래프의 수익금과 잔고: **고른 기간의 첫날에 1,000 USDT 를 넣은 계좌** 기준. 거래내역은 시작한 날 1,000 기준 그대로.
- 고점 부근 추가 입금 경고는 넣지 않는다.
- 테슬라 같은 주식은 "토큰화 주식"으로 표기한다. 지수와 금은 Claude 가 같은 계열로 "토큰화 지수", "토큰화 금"이라 붙였다(이 이름이 어색하면 대안을 내라).
- 카드는 "자세히"가 주 버튼, 상세는 "따라가기"가 주 버튼. 의도한 것.
- 판단 기록의 시각 표기(초까지)와 합니다체는 파운더가 정했다.
- 20종을 반복한 10페이지는 이번 범위가 아니다.

## 구현한 것
| 번호 | 내용 | 위치 |
|---|---|---|
| 1 | 성과 줄 라벨: 최근 30일 수익률, 최근 30일 최대 낙폭, 전체 기간 승률, 전체 기간 거래 수. 도움말 문구도 맞춤 | `mkOvKpi`, `MK_TIP` |
| 2 | 승률 정렬: 전체 기간 거래 20건 미만은 방향과 무관하게 맨 뒤. 100칸으로 자른 뒤에 나눈다 | `tfSS3GridHtml`, `MK_WIN_MIN` |
| 3 | 값이 변하지 않은 기간의 그래프: 눈금에 여유, 기준선과 겹치면 회색 선, "이 기간에는 수익률 변화가 없어요" | `mkdTicks`, `mkdChartHtml` |
| 4 | 달력 머리: "9월 수익률 +17.6%, 끝난 거래 1회". 달의 승률 없음 | `tfSS3CalHtml` |
| 5 | 그래프 기준: 수익금 = 1000×(v/기준-1), 잔고 = 1000×v/기준. 안내 "30일 전에 1,000 USDT를 넣었다면" | `mkdSeries`, `mkdHintTxt` |
| 6 | 정렬 칩에 추천순. 추천순은 방향을 바꾸지 않는다 | `mk3Controls`, `tfSS3SortPick` |
| 7 | 검색에 티커(BTC, NVDA). 주문 표의 종목을 티커로 | `tfSS3GridHtml`, `mkOrdersTable` |
| 8 | 카드 "지금" 줄의 끝 낱말이 혼자 넘어가지 않게 | `mkCard` |
| 9 | 좁은 화면에서 떠 있는 버튼이 카드 버튼이나 페이지 번호와 겹치면 잠시 숨김 | `mkFabDodge` |
| 10 | 상품 표기: 판단 기록의 꼬리표(토큰화 주식 매수 등), 정보 탭의 거래 상품 줄, 낱말 풀이 | `mkInst`, `mkTagIO`, `MK_GLOSS` |
| 11 | 세는 말: 주문은 건, 거래는 회. 따라가기 화면의 날짜를 `YYYY.MM.DD HH:MM` 로 | `mkOrdersSec`, `mkDT` |
| 12 | 따라가기 계산(F1): 수동 정리(`flatI`) 뒤 정리한 돈이 다음 진입에 다시 들어간다. 매입 원금도 이어 간다 | `cpCalc` 의 `stateAt`, `doFlat` |
| 13 | 따라가기 계산(F2): 새 진입 멈춤은 멈춘 봉(`stopI`)을 저장한다. 그때 들고 있던 포지션이 모두 끝나는 봉(`windEnd`)까지만 기준가를 따라가고 현금이 된다. 멈춘 뒤의 입금 대기분은 들어가지 않는다 | `cpCalc`, `mkStopGo`, `cpxPos` |
| 14 | 끝내기는 끝 봉(`endI`)에 적는다. `flatI` 는 수동 정리만. 옛 저장(끝난 계좌에 `flatI` 만 있음)은 끝 봉으로 읽는다 | `cpClose`, `cpCalc`, `mkMigrate` |
| 15 | F3: 끝낸 따라가기에는 대기 금액 안내를 보이지 않는다. F4: 기다리는 돈이 있으면 수익률 차이의 이유를 그것으로 설명 | `cpMixNote`, 자금 이동 표 |

알고 있는 한계(판정해 달라): 13번에서 AI 판단 전략은 여러 종목을 든다. 멈춘 뒤 `windEnd` 까지의 기준가에는 원본이 그 사이 새로 산 종목의 손익도 섞인다. 좌수 방식이 전략 전체의 기준가를 사는 구조이기 때문이다.

## 할 일
1. 15개 항목마다 **통과 / 일부 / 실패**. 근거는 파일:줄과 실제 화면(1440, 390).
2. 12, 13, 14번은 숫자로. 과거 봉에 상태를 놓거나 기록을 잘랐다 복원하는 방식으로, 판단 방식 셋에서 잔고, 내 수익률, 실현과 미실현, 분배, 대기 금액을 손계산과 대조. 입출금 보존식도 확인. 실제 버튼 경로(`cpFlat`, `mkStopGo`, `cpClose`, 예산 조정)로도 한 번.
3. 5번: 세 탭의 끝값이 서로 맞는지(수익률 r 이면 수익금 10r, 잔고 1000+10r). 월별 보기, 전체 기간, 기간을 바꾼 뒤 거래내역 전체 화면에 다녀왔을 때.
4. 새로 생긴 결함을 P0, P1, P2 로. 7개 언어 중 한국어만 본다. 콘솔 오류 확인.
5. 화면 문구에 "데모", "시뮬레이션", "예시"가 새로 들어갔는지.
