# ROUND 1 (Codex, Astra): 제품 모델 후보의 독립 스크린샷 비평

Round 0 교차 검증 뒤 Claude 가 후보를 **제품에 실제로 렌더**했다. Claude 의 비평(`r1-claude.md`)은 아직 보지 말고 독립적으로 평가한다. 평가 대상은 코드가 아니라 아래 PNG 다. 필요하면 직접 다시 띄워 확인(정적 서버 8843, 헤드리스 Chrome 9333, `MK_VAR={name:'A'|'B'|'C',id:'A'|'B1'|'B2',cta:'P0'|'P1'|'P2'}; TF_SEEDS=null; TF_SS_CACHE=null; MK_D30={}; tfShareHub('find')`).

## Round 0 결정 요약 (Claude 최종 판정)
- 세 판단 방식을 모두 채운다. 글로 지어내지 않고 계산기로: `mkAgentRun`(직접 탐색), `mkHybridRun`(혼합), 기존 규칙 엔진(조건 실행). 네가 입증한 회계 결함은 현금과 수량 원장(`mkLedger`)으로 다시 써서 고쳤다. 네 반례 1은 이제 곡선 -0.0999%, 거래 -0.20%(비중 0.5), 반례 2는 열린 포지션 -0.0999% 로 나온다. 체결은 "하루 한 번 종가에서 판단하고 그 종가에 체결". 조건 실행의 익절과 손절도 조건에 닿은 날 종가로 체결(`fill:'close'`).
- 혼합: AI 가 종목을 고르고 시장이 약하면 진입을 보류, 진입과 청산은 규칙.
- 20종의 행동 값은 성과를 보기 전에 정하고 그대로 돌렸다. 결과에 맞춰 다시 고르지 않았다(30일 마이너스 1종, 0.0% 1종, 낙폭 -38% 도 그대로).
- 날짜: 마지막 봉이 어제가 되게 기준을 맞췄다. 가격, 판단 기록, 기간 계산이 모두 봉 번호에서 나오므로 함께 움직인다.
- 유지(사용자 지시): KPI 넷, 버튼 문구, 4열 x 5행, 10페이지 반복. 30일은 수익률만, 나머지 셋은 시작 이후 전체.
- 기간 칩과 위험도 필터 제거, "판단 방식" 선택기 추가, 정렬명 "낙폭 낮은 순".

## 할 일
1. 이름 A, B, C / 식별 A, B1, B2 / 버튼 P0, P1, P2 각각에 대해 Round 0 에서 네가 정한 합격 기준으로 판정하고 **승자를 하나씩** 고른다. 어느 것도 합격이 아니면 제3안을 구체적으로(문구, 치수) 제시.
2. 3초 시험, 10초 시험, 30초 시험을 목록 스크린샷에 적용해 PASS / FAIL 과 근거.
3. 구체 비판 최소 8개(목록 4개 이상, 상세 4개 이상). 형식: `요소 → 문제 → 사용자 해석 → 제안`. 각 항목에 P0 / P1 / P2.
4. 상세 세 장이 유형별로 정보 우선순위가 다른지, 아니면 같은 틀에 문구만 바뀐 것인지 판정.
5. 이름 C 의 20개 목록을 보고(직접 렌더해서 20장 확인) 약한 이름을 지적하고 대안 제시. 금지 사항은 Round 0 과 동일.
6. 구현 검토: `index.html` 의 `/*RD_CORE_BEGIN*/` 블록(계산기와 렌더), `/*MK_CAT_BEGIN*/` 블록. 같은 이름의 앞선 함수를 뒤에서 다시 선언해 대체하는 방식의 위험, 원장 불변식, 미래 참조, 캐시 키, 저장된 상태와의 호환.
