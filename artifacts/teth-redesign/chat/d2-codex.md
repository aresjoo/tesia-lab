# 전략 대화 2라운드 구현 검수

## 1부: 독립 비평

판정: 화면 구성은 채택 가능하지만, 글의 사실과 기록 접근을 고친 뒤 배포한다. **P0 0건, P1 6건, P2 5건**. 아래 F1~F6, U1~U5를 각각 한 건으로 센다.
절차: 이 1부를 파일에 먼저 작성한 뒤 `d1-cross-claude.md`를 읽는다. 제품 파일은 수정하지 않았다.
근거: 제공된 m1 PNG 8장, a1과 b1의 데스크톱 및 모바일 기본 화면을 직접 확인했다. Chrome 9333의 별도 탭에서 저장소 서버 8765를 열어 1440×900, 390×844로 재검증했다.
기준: 요청된 m1 화면과 처음 로드한 `index.html` SHA-256 앞 16자리 `8fe431e57addf90e6`, 데이터 마지막 날 2026.09.28. 브라우저 검증 종료까지 이 해시를 확인했다. 보고서 마감 중 다른 세션 변경으로 `1adf7a3ba3f10d18`이 되었으며, 이후 변경본은 이 판정의 검수 대상이 아니다. 아래 코드 줄 번호도 처음 검수한 버전 기준이다.

### 파운더 지시

- 개요는 성과 다음에 대화가 온다. 아바타, 전략 이름, 시점, 말풍선으로 채팅이 읽히며 별도 설명 패널을 끼우지 않았다. 발화자에 모델명은 없다.

### 발견한 불일치와 뜻이 흐린 문장

- **F1 / P1 / 비교 기준 혼동**: d1② “지금 가장 많이 오른 건 이더리움 +15%, 비앤비 +10%예요”는 상승률 순위가 아니다. 실제 다음 순위는 비트코인 +13.97%, 솔라나 +10.87%다. d2②도 실제 순서는 엔비디아 +26.59%, 비트코인 +11.63%, S&P 500 +11.08%다. d2⑤의 2위도 이더리움 +22.19%가 아닌 엔비디아 +23.83%다. `mkAgentRun`은 상승률을 변동성으로 나눠 순위를 매긴다. “흔들림까지 비교했을 때 앞선 종목은 …”으로 바꾸고 비교 날짜와 20일/60일 기준을 붙인다.
- F1의 같은 기준 문제: “8종 중 4종이 오르고 있었고”는 당일 상승이나 비교 기간의 플러스 종목 수가 아니다. `up`은 60일 평균 위 종목 수다. h2③의 에이다는 60일 -7.37%여도 이 4종에 들어간다. “60일 평균보다 높은 종목이 8종 중 4종이었어요”로 명시한다. h2⑤의 비교도 “60일 평균을 넘은 후보 중”을 붙인다.
- **F2 / P1 / 20일의 구간**: r1③ “최근 20일 중 … 13.4% 아래”는 `mkDipTxt`가 `i-20`부터 `i`까지 가격 21개를 취한 값이다. 최근 20개면 13.1%다. `index.html:18321`과 18322의 구간을 문장과 통일한다. 현 계산을 유지하려면 “20일 전부터 그날까지”로 쓴다.
- **F3 / P1 / 가격과 수익 기준 누락**: “96,670에”, “0.2158에”, “175.7에”는 단위가 없어 통화인지 지수 수준인지 독자가 추측한다. 거래 대상별 실제 가격 단위를 붙인다. h1②는 가격 +10.019%에 팔아 비용 후 +9.800%인데 “결과는 +9.8%”만으로는 목표10% 전에 판 듯 읽힌다. “가격은 10.0% 올랐고, 비용을 뺀 결과는 9.8%예요”로 구분한다. 지금의 `state.open.chg` 역시 비용 후 손익이 아니라 매수가 대비 가격 변화다.
- **F4 / P1 / 조건과 일수 경계**: `mkRules`의 “20% 넘게 … 8% 넘게”는 엔진의 `>=20` / `<=-8`과 다르다. 다른 조건 실행과 혼합도 같다. “20% 이상 … 8% 이상”으로 쓴다. r1의 8/29→9/23은 25일 경과이며 산 날부터 세는 25일째가 아니다. “산 뒤 25일이 지나면”으로 통일하고 r2 지금의 “3일째”, h2의 “13일째”도 “3일/13일 지났어요”로 쓴다. d1의 “33%까지만”도 실값1/3을 엄밀한 상한으로 읽게 하므로 “살 때 자산의 최대 3분의 1”로 바꾼다.
- **F5 / P1 / 연도 누락**: 소개의 3/8, 8/21, 11/29는 2024년 또는 2023년인데 `mkChatRow`는 모두 `mkMD`만 표시한다. 2026년 기록 뒤에 이어져 같은 해로 오독한다. 이전 연도 발화에는 연도를 붙이고 `time`에도 기계가 읽을 날짜를 넣는다.
- **F6 / P1 / 전체 기록의 범위**: “전체 기록”은 활동 탭으로 가지만 `mkLogTab`은 120건에서 끊고 더 읽는 조작이 없다. d1은 원래 이벤트310건, 같은 판단을 묶어도271건이다. 전부 도달할 수 있게 하거나 “최근 판단 기록”으로 바꾼다. 이동 성공만으로 전체 기록 통과라 하지 않는다.
- **U1 / P2 / 어색한 표현**: h1과 h2의 “저는 둘이 나눠서 일해요”는 “저는 종목 고르기와 매매 시점 정하기를 나눠 해요”로 쓴다. 공통 “비교하는 날에 든 종목”은 “다시 비교하는 날, 들고 있는 종목”으로 바꾼다. r2와 h2의 “9월 25일에 24,552에 샀고” 유형은 날짜 뒤 조사를 던다. “산 가격보다 가장 높았을 때”는 “산 가격을 기준으로 보유 중 가장 많이 올랐을 때”로 쓴다. 표본의 종목에 붙는 을/를, 은/는, 이/가에는 별도 오류가 없었다.
- **U2 / P2 / 내용 반복과 조건 우선순위**: 200~300자를 유지하면서 매번 되풀이하는 매도 규칙을 당일 이유나 다음 확인일로 치환한다. h1 첫3개 발화에는 시장4/8종 조건이 없고 뒤 발화에서 처음 나온다. 지금 발화에서는 일반적인 “둘이 나눠”보다 시장 조건을 우선한다. 묶은 기간의 숫자에는 “마지막 비교에서는”을 붙여 기간 내내 같은 수치였다는 오독을 줄인다.
