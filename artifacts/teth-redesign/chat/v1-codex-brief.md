# 판단 기록 글 160편 (Codex, Astra): 사실 대조와 문체 검수

## 배경
파운더가 판단 기록의 글을 nof1 Alpha Arena 모델 채팅의 문체로 다시 쓰라고 지시했다. 1인칭, 입장과 이유, 구체적 수준, 걸리는 점과 감정, 다음에 볼 것. 글 끝의 규칙 설명은 뺀다. 200~300자, 합니다체.
글은 엔진 기록에서 뽑은 자료를 근거로 미리 써서 제품에 넣었다(`index.html` 의 `MK_VOICE`, 고르는 곳은 `mkChatMsgs`).

## 자료
- 문체 규칙: `artifacts/teth-redesign/chat/voice-prompt.md`
- 글마다의 근거 자료: `artifacts/teth-redesign/chat/voice/facts-1.json` ~ `facts-4.json` (전략 5개씩, 전략마다 글 8편)
- 쓴 글: `artifacts/teth-redesign/chat/voice/out-1.json` ~ `out-4.json` (전략 id 아래 열쇠는 자료의 `key`)
- 자동 검사기: `artifacts/teth-redesign/chat/voice/validate.cjs` (길이, 말투, 금지어, 자료에 없는 숫자, 같은 시작). 160편 모두 통과 상태.
- 화면: `artifacts/teth-redesign/chat/v1-d1-1440.png`, `v1-r1-1440.png`, `v1-h1-1440.png`, `v1-r7-390.png`. 직접 렌더해도 된다(`index.html#/share/s/<id>/all`).

## 할 일
1. **사실 대조(전수).** 160편 각각에서 글에 나온 주장(종목, 날짜, 가격, 퍼센트, 일수, 순위, 누가 앞서고 뒤졌는지, 몇 번 중 몇 번, 기준을 넘었는지)을 그 글의 자료와 대조한다. 자동 검사기는 숫자가 자료에 있는지만 본다. 숫자가 맞아도 **뜻이 틀린 문장**(다른 종목의 값을 붙였다, 최고와 최저를 바꿨다, 손절가까지의 여유를 수익으로 읽었다, 직전 거래의 순서를 거꾸로 읽었다, 기준 충족 여부를 반대로 썼다)을 찾는 것이 목적이다. 자료의 `lastThreeClosedTrades` 는 오래된 것부터이고 마지막이 직전 거래다.
2. **자료에 없는 주장.** 자료로 확인할 수 없는 단정(원인 설명, 시장 전체에 대한 말, 앞날에 대한 약속)을 찾는다.
3. **문체.** 문체 규칙 아홉 가지를 지켰는지. 규칙 설명으로 끝나는 글, 감정이나 걸리는 점이 없는 글, 같은 전략 안에서 틀이 반복되는 글을 찾는다. 감정이 자료에서 나오지 않고 꾸며 낸 글도 찾는다.
4. **초보가 잘못 이해할 표현.** 수익을 보장하는 것처럼 읽히는 문장, 뜻이 흐린 낱말.
5. 고쳐야 할 글마다: 전략 id, key, 문제 문장, 자료의 해당 값, 고친 문장 제안.
6. **P0, P1, P2 개수를 명시.** P1 은 사실과 다르거나 뜻이 틀린 글, P2 는 문체와 표현.

## 제약
파일 수정 금지(산출 파일 하나만). em dash, 가운뎃점 금지. 면책 문구나 위험 고지를 요구하지 않는다. 길이와 말투, 1인칭, 감정 표현을 넣는 방향은 파운더 확정. 산출 `artifacts/teth-redesign/chat/v1-codex.md`, 200줄 이내. 고칠 글이 많으면 표로 압축한다.
