# 카드 개선 1라운드: Codex 독립 제안

현재 PNG 두 장을 직접 확인하고 `index.html`의 `mkCard`, `mk30`, `MK_CAT`, `mkMigrate`와 `copy.json`, `cat-data.json`, `agent-core.js`를 대조했다. 아래는 구현 전 제안이다.
핵심은 무엇을 하는 전략인지 먼저 읽고, 누가 등록했는지 구분한 뒤, 성과를 보고 선택하는 카드다.

## 1. 여섯 항목 판정

| 항목 | 판정 | 근거와 보완 |
| --- | --- | --- |
| 1. 최대 낙폭 삭제 | ACCEPT | 카드에서 완전히 뺀다. 30일 수익률과 전체 기간 낙폭의 단순 크기 비교도 사라진다. 없어진 칸은 지우고, 성과 영역을 수익률과 수익 거래 문장의 두 층으로 재편한다. 안전 점수나 별점으로 대체하지 않는다. |
| 2. 초보 말투 | ACCEPT | 종목, 고르는 범위, 사고파는 행동을 한 문장으로 쓴다. 조건 실행에는 AI를 붙이지 않고, 혼합은 AI가 종목을 고른다는 역할까지만 설명한다. 매도 기준은 매수가 대비인지 명시한다. |
| 3. 이름과 등록자 | MODIFY | 추상적인 이름을 행동이 보이는 이름으로 바꾸되 이름만으로 고유성을 해결하지 않는다. 이름 아래 등록자 핸들과 고정 전략 번호를 함께 둔다. 운영자가 만든 전략처럼 보이는 인물 설정이나 경력은 붙이지 않는다. |
| 4. 승률 문장화와 거래 수 삭제 | MODIFY | 거래 수는 삭제한다. 승률은 `전체 기록 기준` 아래 `10번 중 약 6번 수익`으로 바꾼다. 약을 넣어 59%의 환산임을 알리고, 30일 성과와 기간을 구분한다. 10번 미만은 이 문장을 생략하며 총횟수를 다른 이름으로 되살리지 않는다. |
| 5. 따라가는 인원 | MODIFY | 선택받고 있다는 사실을 한 줄로 보여 준다. `1,284명이 따라가는 중`은 활성 이용자 집계가 있을 때만 쓴다. 시선 경쟁을 피하려고 성과보다 작은 중립색으로 두고, 급증 표시나 순위 배지는 붙이지 않는다. |
| 6. 거래소 위치 | ACCEPT | 버튼 줄에서 제거하고 상단 분류 태그 옆에 `Bitget에서 실행`을 둔다. 로고는 생략한다. 테두리, 배경, 클릭 동작 없이 12px 텍스트로 표시해 세 번째 버튼처럼 보이지 않게 한다. |

## 2. 줄 단위 정보 구조

1280px 이상은 목록 2열과 카드 내부 좌우 구성을 유지한다. 카드 안은 왼쪽 약 56%, 오른쪽 약 44%, 간격 20px를 시작값으로 잡는다.
1280px에서 실제 콘텐츠 폭이 좁아지면 설명은 세 줄까지 허용하고 오른쪽 그래프 폭부터 줄인다. 글자 축소로 맞추지 않는다.

| 순서 | 왼쪽: 무엇을 하는가 | 오른쪽: 성과와 버튼 |
| --- | --- | --- |
| 1 | 전략 이름, 18px 굵게, 한 줄 | `30일 수익률`, 12px |
| 2 | `등록자 @핸들  #h1`, 12px | `+9.8%`, 24px와 같은 30일 그래프 |
| 3 | `혼합`과 `Bitget에서 실행`, 필요하면 두 줄 | `전체 기록 기준`, 12px |
| 4 | 새 한 문장 설명, 14px, 두 줄에서 세 줄 | `10번 중 약 6번 수익`, 14px, 한 줄 |
| 5 | `지금 애플 보유 중`처럼 현재 행동, 최대 두 줄 | `640명이 따라가는 중`, 12px, 한 줄 |
| 6 | 현재 행동까지 읽은 뒤 자연스러운 여백 | `따라가기`와 `자세히`, 높이 44px, 동일 너비 |

이름 앞 큰 도식은 생략해 이름 폭을 확보한다. 종목 범위는 설명에 담고, 긴 시장명 태그를 다시 반복하지 않는다.
오른쪽은 수익률, 수익 거래 문장, 참여 인원, 버튼의 네 묶음이다. 기존 3칸 통계 그리드와 가로 구분선을 없애고 묶음 사이 12px에서 16px를 둔다.
버튼은 오른쪽 하단에 정렬한다. 참여 인원이나 수익 거래 문장이 없으면 여백을 남긴다. 다른 수치로 채우거나 수익률을 더 키우지 않는다.
`자세히`의 현재 밝은 채움과 `따라가기`의 외곽선 위계는 유지한다. 성과 숫자의 부호와 손실 색도 유지한다.

1280px 미만은 카드 내부를 세로로 쌓는다. 목록은 641px에서 1279px까지 2열, 640px 이하는 1열을 유지한다.
세로 순서는 이름 → 등록자와 번호 → 분류와 거래소 → 설명 → 지금 상태 → 30일 수익률과 그래프 → 전체 기록 기준과 수익 문장 → 참여 인원 → 버튼이다.
390px에서는 바깥 여백 20px, 카드 폭 350px, 안쪽 여백 18px로 본문 314px를 확보한다. 설명은 두 줄 목표, 세 줄 허용이다.
버튼은 너비를 반씩 나누고 사이 8px를 둔다. 고정 높이 카드나 문장 말줄임으로 첫 화면에 억지로 맞추지 않는다.

매도 설명은 장중 특정 가격 체결을 약속하지 않는다. 엔진은 하루 단위로 확인하며, 조건 실행과 혼합에는 다른 매도 조건과 25일 보유 한도도 있다. 상세 설명에서 이를 유지한다.

## 4. 등록자와 같은 이름 구분

형태는 `등록자 @공개핸들  #전략번호`다. 제목 바로 아래 항상 표시하고 얼굴, 인물 실루엣, 소개 문구, 전문가 배지를 넣지 않는다.
핸들은 중복되지 않는 공개 식별자, 전략 번호는 이름을 바꿔도 유지되는 식별자다. 위 20종은 기존 id를 번호로 사용할 수 있다.
다른 등록자의 같은 이름은 핸들로, 같은 등록자가 올린 같은 이름은 번호로 구분한다. 충돌할 때만 나타나는 임시 접미사는 쓰지 않는다.
`@핸들`은 표시 형식 예시다. 현재 카탈로그의 `name`, `nick`은 전략 이름이므로 등록자 이름으로 재사용하지 않는다. 실제 등록자 연결 전에는 가상의 인물을 만들지 않는다.
검색은 이름, 공개 핸들, 전략 번호를 모두 받도록 제안한다. 목록, 상세, 따라가기 확인창에서 같은 식별 조합을 보여 준다.

## 5. FOMO의 형태와 한도

표시는 오른쪽 버튼 바로 위 한 줄, `1,284명이 따라가는 중`이다. 모바일도 버튼 바로 위이며 12px 중립색, 숫자만 별도로 강조하지 않는다.
수치 예시는 현재 `MK_CAT.fw`의 d1=1,284, h1=640이다. 이는 고정 값이며 활성 이용자 수라는 근거는 없다. 실제 집계 연결 없이 이 문구로 게시하지 않는다.
집계 단위는 해당 전략을 현재 따라가는 고유 이용자다. 한 사람이 여러 계정을 연결해도 한 명이며, 종료와 일시 중지 상태는 제외한다.
1명 이상이면 크고 작은 수를 같은 형식으로 표시하고, 확인된 0명은 `아직 따라가는 사람이 없어요`, 값이 없으면 행을 생략한다. 순위에 따라 숫자를 부풀리지 않는다.
1만 미만은 쉼표가 있는 정수, 1만 이상은 소수 한 자리의 `약 1.2만 명이 따라가는 중`으로 줄인다. 카드 간 집계 시점을 맞춘다.
카드당 사회적 참여 표시는 하나만 둔다. 불꽃, 카운트업, 급증 화살표, 마감 시간, 수익자 수, 얼굴 무더기, 인기 배지는 추가하지 않는다.

## 6. 구현 위험과 검수 기준

- 수익 문장은 `r.winRate`를 10회로 환산해 반올림한다. h1의 58.82%는 `약 6번`이다. `r.n < 10`이나 값 누락이면 생략한다. 이 기준은 환산 표현의 최소 분모이지 신뢰도 등급이 아니다.
- 반올림으로 0번 또는 10번이 되는 중간 비율은 `전체 기록에서 98%가 수익`처럼 원래 비율로 쓴다. 실제 0%와 100%만 0번과 10번을 허용한다. 아직 팔지 않은 거래는 분모에 넣지 않는다.
- `30일 수익률`과 그래프는 계속 `mk30`을 사용한다. 전체 기간 승률을 30일 값처럼 배치하거나 `cat-data.json.m`의 숫자를 화면에 복사하지 않는다.
- 기존 `mk3-stats`의 3열 규칙과 데스크톱 `grid-row`를 함께 교체해야 한다. 내용만 삭제하면 빈 열과 불필요한 구분선이 남는다. 생성 원본 `rd-ui.js`, `rd.css`, `copy.json`과 적용 결과의 일치도 검수한다.
- 이름 기반 `mkMigrate`는 같은 이름을 합칠 수 있다. 이름 변경 전에 즐겨찾기, 검색 결과, 따라가기 연결을 고정 id로 대조하고 등록자 필드와 분리한다. 재명명으로 기존 연결이 바뀌면 실패다.
- 현재 상태의 `반등 대기`, `하락 대기`도 `다시 오르기를 기다리는 중`, `가격이 내려오기를 기다리는 중`처럼 풀어 쓴다. 보유 종목 셋은 두 줄까지 표시해 의미가 잘리지 않게 한다.
- 1440, 1280, 1279, 768, 640, 390px에서 20종 전부를 검수한다. 1280 경계에서 좌우 겹침이 없고, 390에서 수평 스크롤과 버튼 잘림이 없어야 한다.
- 이름은 18px에서 한 줄, 설명은 14px에서 최대 세 줄, 현재 상태는 최대 두 줄을 목표로 한다. 이름, 설명, 전략 번호에는 말줄임과 강제 줄 자르기를 쓰지 않는다. 등록자 핸들만 필요하면 접되 탭과 키보드로 전체를 확인할 수 있게 한다.
- `min-width:0`과 유연한 그래프 폭을 적용하고 `#전략번호`, 수익 문장, 버튼 문구는 보존한다. 긴 영문 핸들, `S&P 500`, 가장 긴 이름, 0명과 큰 인원 수로 검수한다.
- 390px의 기준 본문 폭 314px에서 버튼 각각 153px와 높이 44px를 확보한다. 글자 200% 확대에서는 줄 수 제한을 풀어 높이가 늘어나게 하고, 부동 위젯이 두 버튼을 가리지 않는지 확인한다.
- 사용자 입력 이름과 핸들은 이스케이프하고, 새 문구의 7개 언어 번역과 접근 가능한 버튼 이름을 확인한다. 거래소 텍스트는 탭 순서에 들어가지 않아야 한다.
- 카드에서 없앤 수치의 정렬 버튼이 상단에는 남아 있다. 초보 목록에서는 `낙폭 낮은 순`, `거래 수`도 다음 적용 범위에서 함께 정리하도록 제안한다.

검증 범위: 기존 PNG 시각 확인과 원본 데이터 및 계산 코드 대조를 완료했다. 제안 카드의 실제 렌더, 줄 수, 키보드 동작, 이용자 집계 연결은 미검증이며 위 항목이 구현 수용 기준이다. 이번 산출은 이 문서 한 파일뿐이다.
