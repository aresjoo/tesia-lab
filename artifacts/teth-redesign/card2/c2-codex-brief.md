## 1부: 독립 비평 (UI 기준)
1. 여섯 피드백 각각이 화면에서 해결됐는지 PASS / FAIL 과 근거. 20종 전부를 본다.
   - 1 최대 낙폭이 카드 어디에도 없는가. 수익률보다 큰 음수 숫자가 남아 있지 않은가.
   - 2 설명 20개가 초보 말투인가. 남은 트레이더 용어를 전부 적는다. 엔진 동작(`artifacts/teth-redesign/tools/cat-data.json`, `agent-core.js`)과 어긋나는 문장을 전부 적는다.
   - 3 이름만 보고 하는 일이 떠오르는가. 서로 헷갈리는 이름 쌍. 등록자 표시가 같은 이름 충돌을 풀 수 있는가. 가짜 트레이더 프로필처럼 보이는가.
   - 4 수익 낸 거래 문장이 직관적인가. 환산이 틀린 카드가 있는가.
   - 5 따라가는 사람 표시가 선택을 돕는가, 과한가.
   - 6 거래소 표시가 버튼처럼 보이는가.
2. 시각 검수: 위계, 정렬, 여백, 줄 수, 잘림, 카드 높이, 1280 경계, 390. 요소 → 문제 → 사용자가 하는 해석 → 제안 형식.
3. 회귀: 이전 이름으로 저장된 즐겨찾기와 따라가기, 옛 주소 진입, 검색, 정렬 셋, 판단 방식 전환, 페이지 이동, 상세, 따라가기 시트.
4. **P0, P1, P2 개수를 명시. 0 이면 0 이라고 쓴다.** P0 는 주요 흐름 차단, P1 은 파운더의 여섯 피드백 중 하나가 해결되지 않았거나 초보가 잘못 이해하게 만드는 것, P2 는 다듬기.

## 2부: 교차 검증
`c1-cross-claude.md` 의 판정(특히 REJECT 4건과 MODIFY 4건)과 약점 4건에 ACCEPT / REJECT / MODIFY / TEST. 반박하려면 화면이나 코드의 근거를 댄다. 합의가 목표가 아니다.
