- 왜: Bitget-first 시각 편향은 AGY가 맞다. 그러나 다른 거래소를 "혜택 미적용"으로 표기하는 것은 현행 데이터(4개 거래소 모두 프로모 존재)와 다르고, 페이지 이름에 파트너명을 넣으면 계약 변경 시 IA가 죽는다.
- 기각: AGY "Bitget 공식 파트너십 허브"·"기타 거래소 혜택 미적용" / Claude 원안의 동등 리스트.

## R1 Codex 재반박 반영 (판정 갱신)
- D08 갱신: 종합 점수도, 팔로워 손익 기본 정렬도 폐기(둘 다 시드에 근거 없음, Codex C03·A11·자기 철회). 기본 정렬 = 검증 수익률(선택 기간). 칩: 안정성(MDD) / 거래 수 / 검증 기간. 팔로워 손익 컬럼은 데이터 없으면 "-"(합성 금지).
- D23 성과 출처 배지: 기간이 아니라 출처로 표기(Codex C01). 현행 시드는 전부 백테스트 → 카드·상세에 항상 "검증 기준(백테스트 N개월)" 배지. "라이브"는 실운용 데이터가 있을 때만.
- D24 규칙 카드 문안은 실제 판정식에서 생성(Codex C02): 전봉 RSI < 임계 / 반등 +0.5% 초과 / 이평 괴리 필터(|SMA20-SMA60|/가격 > 3%) / 손절·익절·25봉 청산. 발명 금지.
- D11 갱신(이름): trendFilter는 방향이 아니라 강도 필터이므로 "추세 추종" 금지. 행동 어휘: trendFilter → "눌림목 반등 매수 · 추세 구간", 없으면 rsiTh≤40 → "급락 후 반등 매수", 그 외 "눌림목 반등 매수". 접미 보수형/공격형/장기 유지.
- D25 닉네임은 식별자(URL·cp 조회)로 보존, 제목은 표시 필드로 추가(Codex C04). `#/share/t/<nick>`는 상세 개요 탭으로 연결하되 라우트 유지(C05). 카피 계정 성과(cpCalc)와 원본 성과(tfSS3PdCalc)는 화면에서 구분 표기.

- D27 연결 완료 화면의 "이용료 상쇄" 문장은 derive.coverage가 covered/partial일 때만, 멀티모델 문장은 항상(사실)(Codex C09).
