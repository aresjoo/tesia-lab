# ROUND 1 (전략 찾기 H1, H2, H4, H5, H6 개선안 검수, Codex)

Claude 가 개선안을 냈고 아직 제품에 구현하지 않았다. 너는 안을 실제 화면에 얹어 보고 채점한다. index.html 은 수정하지 말고, 고칠 것을 구체적으로 지적한다.

## 볼 것
- `ux-audit/finder-h/BRIEF.md`: 문제 정의, 대표 결정(고정), Claude 1차 제안(H1 안 1~3, H4 안 A~C, H5 안 1~2, H6 안 1~2), 검토 방식.
- `ux-audit/finder-h/CRIT-claude.md`: Claude 쪽 독립 검토자의 채점. 이 파일을 먼저 읽지 말고, 네 채점을 끝낸 뒤에 읽고 다른 결론이 난 항목만 마지막에 짧게 반박하라.
- 실제 제품: 정적 서버를 직접 띄워 헤드리스 Chrome 으로 `tfShareHub('find')` 와 상세(`tfSS3Go`)를 열어 확인. 저장 상태를 지우고 시작할 것(localStorage.clear 후 새로고침). 상세는 h4(빈 그래프 재현), r1(승률 모순 재현), d3(최대 낙폭 -38.2%)을 반드시 연다.
- 코드 위치: 카드 `mkCard` index.html:17971, 승률 문구 `mkWinTxt` 17963, 성과 줄 `mkOvKpi` 18430 부근, 눈금 `mkdTicks` 16305, 달력 머리 12339, 정렬 17921 부근 `win:function`.

## 답할 것
A. 각 안을 실제 화면에 얹은 스크린샷(1440, 390)을 찍고, 브리프의 6개 기준으로 0~10 채점. 항목마다 근거 한 줄(픽셀 위치나 파일:줄).
B. H1, H4, H5, H6 각각 채택 추천 1개. 합치지 말고 고른다. 추천안에 필수 수정 최대 2개.
C. 구현 안전 점검: `mkOvKpi` 에서 승률과 거래 수를 전체 기간으로 바꿀 때 기간 선택(`mkdSet('per')`)이 성과 줄을 다시 그리는 경로에서 부작용이 있는가. `mkdTicks` 의 최저=최고 처리. H2 정렬 변경이 20종 10페이지 반복 코드(17925 부근)와 어떻게 얽히는가. index.html 은 CRLF 다.
D. 대표 방향 "미니멀하고 직관적"에 비추어, Claude 의 추천이 요소를 늘리는 쪽이면 지적하라.
E. 반드시 고칠 것 목록(우선순위 순, 최대 6개). 문구는 대안 문장까지.
