# CODEX의 히어로 시안 평가

채택 추천은 **claude**다. 제품이 하는 일과 사용자의 통제권이 첫 문장에 함께 드러나고, 영상의 밝기가 달라져도 핵심 문구를 읽기 쉬운 구성이기 때문이다. light는 더 강한 첫인상과 좋은 설명 순서를 갖췄지만, 영상 위 보조 링크의 가독성과 실시간 서비스처럼 보이는 표현을 보완해야 한다. codex 안은 평가에서 제외했다.

## 확인 범위

- `CRITIQUE_BRIEF.md`와 `BRIEF.md`를 읽고, 이미지 읽기 도구로 `mock-claude-d1440.png`, `mock-claude-m390.png`, `mock-light-d1440.png`, `mock-light-m390.png` 네 장을 실제로 열어 전체 구성을 확인했다.
- `current-d1440.png`와 `ref-robinhood.webp`도 실제로 열었다. 두 시안의 HTML, `NOTE-claude.md`, 현재 `index.html`의 사이드바와 `tfIntroView()`를 대조했다.
- `NOTE-light.md`는 평가 시점에 없었다. light의 의도는 화면과 HTML에서 확인할 수 있는 범위만 평가했다.
- 점수는 항목별 0~10점, 동일 가중치다. 3초 이해와 신뢰 점수는 화면에 대한 평가자의 판단이며 사용자 실험 결과가 아니다.
- 제공 PNG의 정지 화면을 평가했다. 영상 전체 루프의 대비 4.5:1 충족, 실제 재생 성능, 자동재생 실패, 키보드 조작과 앱 통합 후 동작은 검증하지 않았다. HTML에서 확인한 설정과 실제 동작 검증을 구분했다.

| 아래 섹션 흐름 | 8 | 전략 세 종류 → 판단 기록 → 시작 단계 → 통제 → 최종 CTA가 논리적이지만, 모바일에서는 세 전략 카드를 모두 지나야 판단 근거를 볼 수 있다. |
| 시각 완성도 | 8 | 세리프 제목, 카드 정렬, 영상 가장자리의 페이드가 일관되지만, 데스크톱 첫 900px에서 다음 섹션 제목이 보이지 않아 화면의 진행감이 약하다. |
| 구현 현실성 | 7 | 300px 그리드와 단일 영상은 단순하고 reduced-motion 정지 이미지도 정의돼 있으나, `.app`과 전역 `.chip` 등의 스타일은 기존 앱에 그대로 이식할 수 없다. |
| **합계** | **63 / 80** | **평균 7.875 / 10** |

**가장 좋은 한 가지:** 거래 기능과 통제권을 한 헤드라인에 담은 점이다. “내 기준대로”를 먼저 읽으므로 초보자도 AI가 아무렇게나 돈을 움직인다는 인상보다 자신이 범위를 정한다는 인상을 받는다.

**반드시 고칠 한 가지:** `.kind`의 “손실 한도는 넘지 않아요”와 `.safe`의 “한도를 넘기 전에”를 고쳐야 한다. 정지 조건과 손실 보장은 구분해야 하며, 현재 프로토타입에서는 실거래 보호 기능이 검증된 것처럼 설명하면 안 된다. 데모의 설정과 모의 정지 동작을 설명하는 문구로 바꾸는 편이 적절하다.

| 1차 CTA 명료성 | 8 | 히어로에 라임 행동이 하나라 시작 버튼은 분명하지만, 바로 밑의 흰 보조 링크와 타일의 강한 빛이 작은 영역에서 시선을 나눠 갖는다. |
| 아래 섹션 흐름 | 9 | 판단 한 장 → 나에게 맞는 방식 → 시작 절차 → 통제 → “오늘은 지켜보기만”이 제품의 근거를 먼저 보여 주고 시작 부담을 낮춘다. |
| 시각 완성도 | 8 | 파란 소제목과 굵은 본문 제목의 위계가 명확하고 마지막 타일이 처음과 이어지지만, 모바일의 반복 카드와 여러 줄 제목은 다소 빽빽하다. |
| 구현 현실성 | 6 | 영상 한 개와 마지막 정지 이미지는 경제적이나, `main`의 300px 여백과 고정 `.side`가 기존 셸과 중복되고 reduced-motion 처리도 없다. |

**가장 좋은 한 가지:** 히어로 바로 다음에 “지금은 기다려요” 판단을 보여 주는 순서다. 초보자가 세 가지 전략 유형부터 학습하지 않아도 무엇을 관찰하고 어떤 이유로 행동을 보류하는지 이해할 수 있다.

**반드시 고칠 한 가지:** `.ghost-link`가 올라가는 영역의 배경을 안정시켜야 한다. light의 전면 영상 구성은 유지하되 보조 링크 뒤의 어두운 면을 충분히 확보하고, 데스크톱과 모바일의 전체 루프에서 글자 대비를 확인해야 한다. 현재 PNG만으로 대비 수치를 충족한다고 판정할 수 없다.

## 구현 판단의 근거와 한계

- 두 안은 브리프의 300px 가짜 사이드바를 구현했다. 현재 앱의 기본 `.g-side` 선언은 256px이고 모바일은 별도 드로어다(`index.html:518`, `index.html:1580`). 현재 참고 PNG에서는 사이드바가 보이지 않는다. 브리프의 목업 규격을 지킨 점은 인정하되, 실제 앱에서는 펼침과 접힘 상태의 콘텐츠 폭을 다시 확인해야 한다.
- 현재 `tfIntroView()`는 `gContent()`에 본문을 넣으며 비회원 CTA에 `authOpen('signup')`을 연결한다(`index.html:14362`). 두 목업의 시작 링크는 `href="#"`다. 따라서 CTA 점수는 시각적 명료성 점수이며 가입 연결 성공을 뜻하지 않는다.
- claude의 전역 `:root`, `.chip`, `.step` 등과 light의 전역 `:root`, `main`, `.card` 등은 이식 전에 랜딩 영역 안으로 범위를 좁혀야 한다. 기존 사이드바를 유지한 채 본문만 넣어야 하며, 목업 셸을 함께 복사하면 여백이나 내비게이션이 중복될 수 있다.
- `halo.mp4`는 738,609바이트이고 poster는 29,428바이트다. 파일 용량만으로 성능 문제를 단정할 이유는 없다. 다만 claude의 마스크와 합성, light의 전면 영상과 그라데이션 비용은 실기기 측정이 필요하다.
- claude는 `prefers-reduced-motion`에서 영상을 숨기고 poster를 보이도록 정의한다(`mock-claude.html:139`). 이는 재생 중지나 네트워크 요청 중지까지 입증하지 않는다. light HTML에는 해당 설정이 없다.
- 신뢰 평가는 현재 저장소가 실거래 없는 데모라는 조건을 두 안에 동일하게 적용했다. light의 “왜?” 재설명과 출금 권한 설명, claude의 거래 권한 설명도 제품에 실제로 연결됐다고 확인한 것은 아니다.

## 채택 추천과 필수 수정

**claude 하나를 채택한다.** 명확한 제품 설명과 영상으로부터 분리된 문구가 처음 방문한 사용자의 이해에 더 유리하다. claude의 헤드라인, 영상 배치와 섹션 순서를 유지한다.

1. **데모 상태에 맞게 신뢰 문구를 정리한다.** 예시 기록에만 표시된 데모 범위를 거래 연결과 통제 설명에도 분명히 하고, 손실 한도를 보장하는 문장은 설정 및 모의 동작 설명으로 바꾼다.
2. **데스크톱 히어로 높이를 줄인다.** `.floor` 높이와 첫 섹션의 상단 여백을 조정해 1440×900 첫 화면 아래에 “이런 전략을 돌려요” 제목과 설명의 시작이 보이게 한다. 모바일의 두 줄 헤드라인과 타일 중심 크롭은 유지한다.
3. **기존 랜딩 본문에 맞게 통합한다.** 목업 셸을 제외하고 스타일 범위를 한정하며 시작 CTA는 기존 인증 동작에 연결한다. 사이드바 펼침과 접힘, 390px 상단 바, reduced-motion에서 영상 재생을 멈추는 동작까지 통합 후 검증한다.

이 문서는 평가와 채택 조건을 기록한 산출물이다. 위 수정은 구현하지 않았으며 제품 코드와 시안 코드는 변경하지 않았다.
