# ROUND 2: Claude 안 반박

판정: 제목 길이는 기각 사유가 아니다. 소개 20개를 현재 CSS에 넣으면 데스크톱에서 전부 잘리고, 행동 약속은 여러 곳에서 엔진을 벗어난다. 승률과 거래 수 7쌍은 산술적으로 불가능하다. 전략별 가격을 계산할 때만 교체해서는 상세와 따라가기의 정합성이 보장되지 않는다.

## 2. 이름만으로 자산과 행동을 알 수 있는가

O는 직접 드러남, △는 은유나 성격만 암시, X는 없음이다. 행동 O도 실제 엔진 지원을 뜻하지 않는다.

## 4. 전략별 가격과 오프라인 탐색의 위험

Claude R1은 가격 전달 API를 제시하지 않았다. 따라서 아래는 “계산 전 전역 PRICE를 A로 교체하고 종료 후 복원”하거나 “마지막 계산의 PRICE를 남기는” 구현을 택했을 때의 구체적인 실패다. 아직 구현된 버그라고 주장하는 것은 아니다.

| 호출 지점 | 전역 교체로 생기는 실패 |
| --- | --- |
| `runBacktest` L5631, L5635~5648 | 가격 출처를 인자로 받지 않는다. 마지막 교체 배열에 따라 같은 params의 결과가 달라진다. 반환 trades에는 체결가도 데이터 ID도 없다. |
| `tfRankSeeds` L11076~11080, `tfSSRows` L11112 | 1차 계산 후 목록에서 다시 돌린다. 선별 단계만 감싸면 행의 `s.r`가 다른 가격으로 덮인다. |
| `tfSS3PdCalc` L11924~11930 | 전체 탭은 저장 `s.r`, 1년/2년은 현재 PRICE로 재계산한다. 기간 변경 순간 자산 경로가 갈라진다. 캐시에 가격 버전도 없다. |
| `mkTradesTable` L16143~16147 | 손익은 A의 `x.pnl`, 표의 진입/청산가는 현재 PRICE에서 읽는다. 계산 후 복원하면 원래 가격, 복원하지 않으면 마지막 상품 B 가격이 나온다. |
| `mkRuleEval` L15990~15992, `mkOpenPos` L15996~15998 | A의 거래 이후를 B 가격으로 재생하면 보유 여부와 진입일을 새로 발명한다. |
| `mkStatusHtml` L16020, L16026 | 개요의 “지금 보유”와 조건 충족 수가 A 성과와 다르게 표시될 수 있다. |

동기 함수끼리 실행되는 동안 자바스크립트가 자동으로 병렬 실행된다는 주장은 하지 않는다. 문제는 계산과 렌더의 시점 분리, 중첩 호출, 예외 복원, 캐시와 여러 상품의 동시 표시다. `try/finally`는 PRICE 복원만 보장하고 결과의 가격 출처까지 보장하지 않는다.

## 5. 소개문과 실제 엔진의 충돌

실제 진입은 전봉 RSI 임계 미달, 현재 봉 +0.5% 초과, 선택적 이평 괴리 절댓값 3% 초과다(L5637~5640). 청산은 SL, TP, 25봉 순서다(L5643~5645). 봉 마감 검사(L16013)이며 뉴스, 장중 급등 감지, 구간 번호, 감정 분석은 없다.

## 6. 수익률, 낙폭, 승률, 거래 수 검산

30일 수익률과 전체 기간의 나머지 세 지표를 구분한다. 전체 거래 수로 30일 수익률을 바로 역산하지 않는다. TP를 T, SL의 절댓값을 L, 승률을 p라 하면 모든 승리가 TP, 모든 패배가 SL인 가정의 1회 산술 기대값은 `E = p*T - (1-p)*L - 0.2` 퍼센트다. 0.2는 엔진 기본 거래 비용(L5632, L5647)이다. E는 표시 승률을 사용한 근삿값이며 실제 시간 청산의 평균 손익을 대신하지 않는다.

## 8. Claude R2 반박 1~6의 처리

| 반박 | 결정 | 근거와 수정할 입장 |
| --- | --- | --- |
| 1. Codex 이름은 자산과 행동이 안 보인다 | 부분 수용, 대칭 적용 | “모나”, “루프 7”의 이름 단독 의미가 약하다. 다만 내 R1 소개는 모두 자산을 받치며 Claude도 자산 직접 노출은 8/20, #6은 소개에도 없다. “고유명사 3~4개”라는 개수는 검증된 기준이 아니다. 카드 전체의 첫 독해로 판단한다. |
| 2. 없는 규칙을 카피가 약속한다 | 수용, 범위 오인만 정정 | 내 R1은 원장과 활동/현재 상태/설정 소비자를 바꾸라고 적었으므로 “원장만 넣고 활동을 유지”한 제안은 아니다. 그래도 분할, 야간, 돌파를 새로 지원하는 비용을 낮게 보았다. 이번 범위에서는 미지원 행동을 빼는 쪽으로 수정한다. 정확히 9종 엔진이 필수라는 개수까지 증명된 것은 아니다. |
| 3. Claude는 기존 다섯 축으로 카피를 입증한다 | 재반박 | 규칙 축을 제한하는 선택과 문구가 실제 규칙이라는 주장은 다르다. #5 뉴스, #11 무기한 보유, #12 TP 이전 청산 금지, #15 두 번째 구간은 기존 축으로 입증되지 않는다. #15/#17은 적힌 파라미터까지 같다. |
| 4. 30일은 수익률만이다 | 수용 | 내 R1의 전 지표 30일 통일은 철회한다. 전체 거래 수로 유지하며 화면의 기존 기간 설명을 명확히 한다. 30일 89회는 현재 일봉 엔진으로 불가능하다. 5회 승률의 약한 표본도 인정하되 표본 신뢰성과 분수 계산의 정확성은 별개다. |
| 5. 가상자산 4종은 다양성을 줄인다 | 수용 | 내 BTC 7/ETH 6 집중은 원래 자산 분산 요구를 축소했다. 앱 후보 자산 범위를 유지한다. 다만 자산명과 거래소 로고의 조합만으로 실제 거래 가능한 상품이라고 결론 낼 수 없으며 페어 매핑은 따로 확정해야 한다. 이번에 외부 상품 지원 여부를 조사한 것은 아니다. |
| 6. Codex 소개의 말투와 길이가 균일하다 | 부분 수용, 수치는 정정 | 실제 R1 표에서 “요” 종결은 14개가 아니라 11/20, 공백 포함 길이는 17~20자가 아니라 17~21자다. 길이가 좁은 범위에 몰린다는 비판은 수용한다. 그러나 Claude 원문은 D에서 전부 2줄이며 “합니다”와 “팝니다” 혼합만으로 행동 다양성이 생기지 않는다. 두 줄 허용과 안전한 문장 길이 변주는 채택한다. |

검증 완료: 두 뷰포트의 20개 이름과 소개, 2줄 제한, SVG 소스와 지정 PNG, 20개 기대값과 승수 분수, PRICE 소비자 추적. 브라우저 JavaScript 예외 0건. 미검증: 다른 OS 폰트, 나머지 반응형 폭과 번역, 이름을 가린 아바타 식별 실험, 20개 목표 원장 생성과 MDD 재현, 실제 거래소 상품 지원. 제품 반영을 주장하지 않는다.
