## 반박하는 것
1. **"이게 정말 사용자가 누르고 싶은 카드인가?"**
   "모나", "루프 7", "파란 우산", "종이비행", "먼바다", "느긋한 봉봉" 은 기억에는 남아도 1초 안에 자산도 행동도 안 보인다. 사용자는 이름에서 "무슨 자산, 무슨 행동, 무슨 성격" 의 감을 원했다. 고유명사형은 20개 중 3~4개까지만, 그리고 한줄소개가 자산과 행동을 바로 받쳐야 한다.
2. **"개발 편의를 위해 카피 품질을 희생하지 않았는가?"**
   반대 방향의 문제다. 카피를 위해 없는 기능을 약속했다. 돌파 진입(S03, S07, S17), 야간 시간대(S15), 분할 매수와 분할 익절(S10, S16), 박스 양 끝 매매(S12), 세 번 지킨 지지선(S14) 은 엔진에 없다. 이걸 뒷받침하려면 규칙 유형 9종과 판정 이벤트 원장을 새로 만들어야 하고, 따라가기 설정(손절, 익절 조정 후 재검증)도 유형별로 다시 짜야 한다. 이번 과제의 다섯 항목(이름, 소개, 아바타, 성과, 차별화)을 넘어선다.
   원장만 만들고 규칙, 활동 탭을 그대로 두면 Codex 가 스스로 기각한 "상세와 즉시 분리" 가 된다.
3. **"전략 간 차이가 이름만 다른 것이 아닌가?"**
   Codex 안은 차이를 규칙 유형에 두었지만 구현되지 않으면 이름만 다른 것이 된다. Claude 안은 엔진이 실제로 가진 다섯 축(기다림의 깊이, 익절 폭, 손절 폭, 방향 필터, 운용 기간)으로만 차이를 만든다. 축은 적지만 화면의 규칙, 활동 기록, 체결 이력이 카피를 그대로 입증한다.
4. **카드 네 지표를 전부 30일로 통일하자는 제안**
   사용자 지시는 "30일 기준으로 적어두자, 수익률만" 이다. 낙폭, 승률, 거래 수는 운용 전체 기간을 유지한다. 30일에 89회 거래는 일봉 엔진에서 불가능하고, 승률 5건짜리는 의미가 약하다.
5. **자산을 가상자산 4종으로 한정**
   사용자가 나스닥, S&P 500, 테슬라, 엔비디아, 애플, 금을 후보로 직접 들었고 기존 목록에도 있었다. 20장이 BTC 7, ETH 6 이면 "몇 개 자산만 반복" 이라는 원래 불만이 그대로다. 11개 자산으로 분산한다.
6. **"AI가 자동 생성한 것처럼 보이지 않는가?"**
   Codex 소개문 20개 중 14개가 "~요" 로 끝나고 길이가 17~20자로 균일하다. 길이와 말투가 고르면 한 사람이 쓴 티가 난다. 짧은 것(12자)과 긴 것(2줄)을 섞는다.

## Codex 안에서 가져올 이름 후보
엔진이 실제로 할 수 있는 행동과 맞는 것만: "한 박자 늦게"(반등 확인 후 진입), "퇴근한 고래"(거래 드묾), "끝까지는 안 가"(작은 익절), "리플 잔돈", "솔라 급행", "바닥 확인서". 최종 20개에서 Claude 안의 약한 이름과 교체 검토.

## 한줄소개 길이
사용자 예시("테슬라가 과하게 밀렸을 때 반등만 짧게 노립니다", 27자)는 238px 한 줄에 안 들어간다. 소개 영역을 2줄 고정 높이로 바꾸고, 문장은 1줄짜리와 2줄짜리를 섞는다. 카드 높이는 모두 같게 유지.
