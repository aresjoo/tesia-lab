방향은 맞습니다. 다만 **수익이 낮다는 이유로 규칙을 고치도록 몰면, 손실을 줄이려고 만든 전략까지 바꾸게 됩니다.** `FLOWS.md` 2절의 다음 행동을 해결하되, 3절의 실행 중 전략 수정과는 구분해야 합니다.

1. **잘못되거나 빠진 점**

   - **낮은 수익을 실패로 단정합니다.** S1은 보유보다 수익이 낮지만 가장 크게 내려간 폭도 53.1%에서 27.8%로 줄었습니다. 사용자가 원했던 장점을 없애는 수정이 나올 수 있습니다.
   - **관찰을 원인으로 단정합니다.** “8%에 팔아서 수익이 낮았습니다”는 비교 검증 전에는 가설입니다. 보유 일수가 25%라는 사실만으로 더 오래 보유하라고 제안해서도 안 됩니다.
   - **공개 전략의 규칙을 가져올 수 있다고 가정합니다.** 현재 복사 흐름은 원본 거래를 따라가는 방식입니다. 공개되지 않은 규칙은 재현할 수 없습니다. 가져올 수 있는 조건과 새로 정해야 하는 조건을 구분해야 합니다.
   - **복귀와 실패 경로가 없습니다.** 원래 대화가 없거나 AI 응답이 실패해도 결과를 보존하고 직접 수정 요청을 입력할 수 있어야 합니다. 실행 중인 전략이라면 수정본 검증이 기존 운용을 바꾸어서는 안 됩니다.
   - 기간과 금액 링크는 내려도 됩니다. 다만 결과 상단의 검증 조건에서 설정 화면으로 돌아갈 길은 남겨야 합니다.

2. **‘나쁨’ 기준**

   **“시작한 돈보다 줄었거나, 같은 기간 그냥 보유한 것보다 수익이 낮으면 수정 검토를 먼저 제안한다”**를 추천합니다. 둘 중 하나만 해당해도 적용합니다. 초보자가 화면의 숫자로 이유를 확인할 수 있습니다.

   이것은 버튼 우선순위 기준입니다. 전략에 ‘나쁨’ 딱지를 붙이는 기준으로 쓰지는 않습니다. 손실 폭이 줄었다면 함께 설명합니다. 거래가 없거나 계산이 불완전하면 별도로 **“결과를 판단하기 어렵습니다”**로 처리합니다. 이 기준을 통과했다는 이유만으로 ‘좋은 전략’이라고 부르지도 않습니다.

3. **TETH가 먼저 제안합니다**

   초보자에게 “무엇을 유지하시겠습니까?”부터 물으면 규칙을 해석하는 숙제부터 생깁니다. **근거가 있는 변경 하나와 그 대가를 먼저 제시**하고 선택하게 합니다.

   처음부터 2~3개를 동시에 바꾸지 않습니다. 하나씩 바꿔야 결과가 달라진 이유를 이해할 수 있습니다. 더 오래 보유하는 제안에는 손실 폭도 커질 수 있다는 설명을 붙입니다.

4. **덮어쓰지 않고 새 버전으로 저장합니다**

   대화할 때마다 만들지 말고, **변경 내용을 확인하고 다시 검증할 때** 만듭니다. 비교 화면에는 다음이 필요합니다.

   - 바뀐 규칙의 이전 문장과 이번 문장
   - 같은 기간, 시작 금액, 가격 데이터와 계산 조건으로 비교했다는 표시
   - 이전과 이번의 수익률, 가장 크게 내려간 폭, 거래 수
   - 최초 결과와 직전 결과를 다시 볼 수 있는 기능

   “이전 +47.1% → 이번 +N%”만으로는 부족합니다. 결과가 나빠져도 남기고, 조건이 달라졌다면 규칙 수정의 효과처럼 보여 주지 않습니다. 같은 기간에서 좋아진 뒤에는 다른 기간에서도 확인할 길이 필요합니다.

5. **정확한 문구**

   버튼은 다음을 권합니다. 좋은 결과에서는 실행 준비를 첫 번째로 올립니다.

   | 위치 | 문구 |
   |---|---|
   | 내 전략의 기본 행동 | **규칙 수정하기** |
   | 두 번째 행동 | **다른 전략 만들기** |
   | 세 번째 행동 | **이 전략 실행 준비하기** |
   | 공개 전략의 기본 행동 | **이 전략을 바탕으로 내 전략 만들기** |
   | 변경 확인 후 | **수정한 규칙으로 다시 검증하기** |

   창업자 사례의 첫 발화:

   > 이번 전략의 수익률은 +47.1%이며, 같은 기간 비트코인을 그냥 들고 있었다면 +273.4%입니다. 비트코인을 보유한 날은 전체 기간의 25%입니다. 먼저 ‘산 가격보다 8% 오르면 파는 조건’을 바꾸어 비교할 것을 제안합니다. 더 오래 보유하면 수익과 손실 폭이 모두 커질 수 있습니다. 사는 조건은 유지하고, 파는 기준만 8%에서 12%로 바꾸어 검증할 수 있습니다. 12%는 비교를 위한 값이며, 더 좋은 결과를 뜻하지는 않습니다.

   선택 칩: **“12%로 바꾸어 비교하기”**, **“다른 수정 요청하기”**. 실제 변경 전에는 바뀔 규칙을 한 번 보여 줍니다.

6. **80%의 가치를 주는 저렴한 대안**

   **“규칙 수정하기”로 기존 대화를 열고, 결과 요약과 현재 규칙을 붙인 수정 요청 초안을 입력창에 넣습니다.** 사용자가 고쳐서 보내게 합니다.

   자동 개선안, 별도 새 전략 분기, 전체 버전 관리 화면은 미룹니다. 대신 수정 전 규칙과 결과 한 벌은 보존하고, 같은 검증 조건으로 다시 돌립니다. 사용자가 막힌 핵심인 **“기간이 아니라 전략을 고치고 싶습니다”**부터 해결할 수 있습니다.
